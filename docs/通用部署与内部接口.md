# FlyMail Custom 部署与内部接口

本文适用于独立部署的通用定制版 FlyMail，不依赖任何具体业务系统。

## 1. 部署要求

- Linux 服务器，推荐 Ubuntu 22.04 或 24.04
- Docker 与 Docker Compose
- 2 GB 以上内存
- 一个未占用的 TCP 端口，或一个可配置 HTTPS 的域名

## 2. 全新部署

```bash
git clone <你的私有仓库地址> /opt/flymail
cd /opt/flymail
cp .env.example .env
```

编辑 `.env`，至少替换以下配置：

```env
APP_PORT=5700
FLYMAIL_ADMIN_USERNAME=admin
FLYMAIL_ADMIN_PASSWORD=<强密码>
FLYMAIL_SESSION_SECRET=<至少32位随机字符串>
FLYMAIL_DB_PASSWORD=<数据库密码>
FLYMAIL_DB_ROOT_PASSWORD=<数据库Root密码>
```

随机值可以使用以下命令生成：

```bash
openssl rand -hex 32
```

启动并验证：

```bash
chmod 600 .env
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:5700/api/health
```

持久化数据默认位于：

- `./data`：缓存邮件、附件与日志
- `./mysql`：MariaDB 数据

上述目录和 `.env` 均已被 `.gitignore` 排除，禁止提交到 Git。

## 3. 通用内部接口

内部接口默认不可用。需要先在 `.env` 设置随机 Token：

```env
FLYMAIL_SERVICE_TOKEN=<随机字符串>
FLYMAIL_DEFAULT_ACCOUNT_ID=
```

调用时统一携带：

```http
X-FlyMail-Service-Token: <随机字符串>
```

可用接口：

```http
GET /internal/api/accounts
GET /internal/api/messages?account_id=...&folder=INBOX&page=1&page_size=50
GET /internal/api/messages?account_id=...&query=关键词
GET /internal/api/messages/{uid}?account_id=...&folder=INBOX
GET /internal/api/messages/{uid}/attachments/{part_number}?account_id=...
GET /internal/api/messages/{uid}/raw?account_id=...
```

接口只读取 FlyMail 已缓存的数据；邮件同步仍由 FlyMail 自己的定时任务和 IMAP 监听负责。

## 4. 迁移已有实例

完整迁移必须同时保留：

1. `.env` 中的 `FLYMAIL_SESSION_SECRET`
2. MariaDB 数据
3. `data` 目录中的附件和邮件缓存
4. 如有下游调用，保留 `FLYMAIL_SERVICE_TOKEN`

切换前先停止旧实例写入，再备份数据库和文件。新实例验证通过后再修改域名或调用方地址，避免新旧实例长期同时同步同一邮箱。

## 5. 更新与回滚

更新前备份 `.env`、`data` 和 `mysql`，然后执行：

```bash
git pull --ff-only
docker compose up -d --build
curl -fsS http://127.0.0.1:${APP_PORT:-8080}/api/health
```

生产环境建议在 Nginx 后使用 HTTPS，不要把内部接口 Token 暴露给浏览器端。
